# Deployment

This guide covers deploying the automated profile for `davidokothminyika-commits`:
the GitHub Actions workflows, the secrets they need, and the procedure for
publishing the generated README and SVG assets.

## What deployment means here

Publishing the profile means committing two generated outputs to the
repository's default branch:

- `README.md`, rendered from `main.mustache` with the configured public data, and
- `assets/generated/banner.svg`, `assets/generated/languages.svg` and
  `assets/3d/profile-3d-contrib*.svg`.

The publish flow is fail-closed: if collection, validation or publishing fails,
nothing tracked is updated and the previously published output is preserved.

## Prerequisites

- Node.js 26 LTS and npm 11 or newer locally.
- A GitHub profile repository named `davidokothminyika-commits/davidokothminyika-commits`.
- A read-only personal access token for collection (see
  [CONTRIBUTING.md](../CONTRIBUTING.md#environment)).
- The **Include private contributions on my profile** setting enabled under
  _Settings → Public profile → Contributions & Activity_ so private activity
  counts toward the contribution calendar.

## Secrets

| Secret                 | Required for                 | Notes                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PROFILE_GITHUB_TOKEN` | `collect.yml`, `publish.yml` | Read-only token that can see every owned repository and the profile's contribution calendar. Classic token: `read:user` and `repo` scopes (`repo` is read-only in this project's use). Fine-grained token: read-only permissions for Metadata and Contents on all owned repositories, plus profile read. |

The publish workflow uses the automatic `GITHUB_TOKEN` (workflow-scoped,
`contents: write`) to push the generated assets. It never uses
`PROFILE_GITHUB_TOKEN` for publishing.

Set the secret under _Settings → Secrets and variables → Actions → New
repository secret_.

## Workflows

| Workflow      | Triggers                        | Purpose                                                                |
| ------------- | ------------------------------- | ---------------------------------------------------------------------- |
| `ci.yml`      | push and pull request to `main` | Format, configuration validation, lint and the full mocked test suite. |
| `collect.yml` | weekly schedule and manual run  | Verify authenticated access and run the collection pipeline.           |
| `publish.yml` | weekly schedule and manual run  | Full publish: collect, render, validate, stage, publish and push.      |

### What `publish.yml` does

1. Check out the repository and install dependencies.
2. Verify authenticated GitHub access (`npm run auth:check`).
3. Run the collection pipeline and publish the Markdown README and the banner
   and language-chart SVGs (`npm run publish`). The script validates the
   rendered output and stages it before moving it onto its target.
4. Generate the three 3D contribution graph variants by running
   `yoshi389111/github-profile-3d-contrib` pinned to the reviewed commit
   `7d95e7d4cdc028dd1e1cbd957d65f35efb12ae39` (tag `v0.9.3`).
5. Validate the generated 3D SVGs and publish them onto their configured
   targets (`npm run publish:3d`).
6. Commit and push the published assets back to the repository with the
   workflow-scoped `GITHUB_TOKEN`.

The workflow grants only `contents: write` and serialises runs with a
single-concurrency group, so deployments never overlap.

## First deployment

1. Set the `PROFILE_GITHUB_TOKEN` repository secret.
2. Ensure the account's private contribution setting is enabled.
3. Push the workflows and configuration to `main`.
4. Open _Actions → Publish profile README → Run workflow_ and watch the run.
5. Verify the published `README.md`, `assets/generated/` and `assets/3d/` on
   GitHub; the repository's profile page should show the generated README.

## Local verification and dry run

```bash
nvm use
npm ci
cp .env.example .env   # populate PROFILE_GITHUB_TOKEN
npm run validate       # config validation + lint + tests
npm run auth:check
npm run collect        # public-safe summary, writes nothing
npm run publish        # generate, validate, stage and publish the README + SVGs
npm run publish:3d     # validate and publish the 3D graphs generated by the upstream action
```

`npm run publish` is a full publish into the working tree; it is not a dry run.
Use `npm run collect` and `npm run test:coverage` for safe local validation.

## Rolling back

The publish flow never deletes tracked output; the previous published assets
stay in the repository history and in `git`'s index until a new commit lands.
To revert, either revert the publish commit or re-run the publish workflow from
a reverted configuration. If a publish run fails midway, published-but-staged
files are already content-validated; the previously published README and assets
remain in place until a new successful publish lands.

## Troubleshooting

| Symptom                                | Check                                                                                                                  |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `PROFILE_GITHUB_TOKEN: not configured` | The repository secret exists and the `auth:check` / `collect` / `publish` step `env` blocks pass it through.           |
| `auth:check` fails                     | Token expiry, account ownership, SSO authorisation, scopes, and the private contribution setting.                      |
| Publish aborts with a validation error | Read the full error; it names the failing stage. Fix the configuration or generator input, not the validation.         |
| 3D graph is empty or stale             | `profile-3d-contrib/` must be produced by the upstream action before `npm run publish:3d` runs.                        |
| Workflow does not commit anything      | The `contents: write` permission is set, the branch protection rules allow the push, and there were changes to commit. |
